# Handoff: Трекни — сервис заказа музыки в заведениях по QR

## Overview
Трекни (Trekni) — сервис, позволяющий гостю заведения заказать музыку через QR-код: гость сканирует код на столе, попадает на страницу конкретного заведения, выбирает трек из разрешённого плейлиста, платит через СБП, и оплаченный трек автоматически встаёт в очередь и играет на плеере у колонок — **без диджея**. Заведение управляет плейлистом, ценой заявки, приёмом заказов и расписанием; платформа удерживает комиссию по тарифу и ведёт выплаты.

Прототип покрывает четыре роли из ТЗ:
1. **Посетитель** — мобильный гостевой флоу (скан → выбор → оплата → очередь).
2. **Владелец / управляющий** — десктоп-кабинет (плейлист, цена, QR, статистика, выплаты, юр. чистота, брендинг).
3. **Плеер у колонок** (автоматический, вместо диджея) — экран 16:9 «сейчас играет + очередь + бесконечный фон». Управлять им на ходу можно с **мобильного пульта смены**, который открывается только из кабинета.
4. **Администратор платформы** — десктоп-админка (заведения, модерация, финансы, споры).
Плюс: **лендинг** для подключения заведений и экран **направлений стиля** (исследование).

## About the Design Files
Файлы в этом пакете — **дизайн-референсы, сделанные в HTML** (формат Design Component, `*.dc.html`). Это прототипы, показывающие задуманный внешний вид и поведение, **а не продакшн-код для прямого копирования**. Задача — **воссоздать эти экраны в среде целевого кодовой базы** (React/Vue/Next/SwiftUI и т.д.) по её принятым паттернам и библиотекам. Если среды ещё нет — выбрать подходящий стек (рекомендация: React + TypeScript, любой headless-UI + собственные токены) и реализовать дизайн там.

Каждый `.dc.html` — самодостаточная страница: открывается в браузере напрямую. Разметка использует инлайновые стили (не копировать буквально — переносить в систему токенов целевого проекта). `ios-frame.jsx` — это рамка iPhone только для показа мобильного экрана в вебе; в реальном приложении она не нужна (гостевой флоу — это адаптивная мобильная веб-страница). `support.js` — рантайм формата прототипа, в продакшн не переносится.

## Fidelity
**High-fidelity (hifi).** Финальные цвета, типографика, отступы, состояния и микроанимации. UI следует воссоздать пиксель-в-пиксель, но средствами дизайн-системы целевого проекта (свои компоненты кнопок/инпутов/карточек с этими токенами), а не переносом инлайновых стилей.

Дизайн-направление — **«Пульс»**: тёмный «ночной клубный» интерфейс, неоновый маджента-акцент, эквалайзеры, моноширинные подписи-данные. Один акцентный цвет заведения кастомизируется (платная опция).

### Typography
- **Дисплей/заголовки:** `Unbounded`, weight 700/800. Крупные цифры KPI, названия, CTA. letter-spacing слегка отрицательный на больших (-0.01em), крупный положительный на вордмарке (3–4px).
- **Текст/UI:** `Onest`, weight 400–700. Основной интерфейсный шрифт.
- **Данные/подписи/лейблы:** `IBM Plex Mono`, weight 400–600. Цены, время, статусы, служебные метки (часто UPPERCASE, letter-spacing 1–3px, 9.5–12px).
- Масштаб (примерно): 38 (hero), 26–32 (KPI/заголовки экрана), 18–23 (крупные названия), 15–16 (body), 13–14 (UI), 11.5–12.5 (подписи), 9.5–11 (мета/лейблы). Мобильные размеры — не мельче 11px мелкого текста, CTA 14px.

### Radius
`999px` пилюли и круглые кнопки · `22–24px` крупные карточки/шиты · `18–20px` карточки · `14–16px` вложенные блоки/инпуты · `9–12px` мелкие плитки/чипы.

### Shadows / glow
- Акцентное свечение кнопки: `0 10px 34px rgba(248,73,166,0.35)` (масштабируется цветом акцента).
- Тост: `0 14px 40px rgba(0,0,0,0.5)`.
- Экран плеера: `0 30px 90px rgba(0,0,0,0.6)`; обложка — `0 20px 50px rgba(0,0,0,0.5)`.
- Выдвижная панель (drawer): `-24px 0 70px rgba(0,0,0,0.55)`.

### Spacing
Шаг ~ 4px: используются 6/8/10/12/14/16/18/20/22/26/28/32/40/44px. Внутренние отступы карточек 18–26px, gap в сетках 14–16px.

### Motion
- `eq` — эквалайзер: `scaleY(0.3→1)`, 0.7–1.2s, `ease-in-out`, `infinite alternate`, разные задержки на полосах.
- `slideUp` — шит оплаты снизу: `translateY(60px)→0`, 0.32s `cubic-bezier(0.2,0.8,0.2,1)`.
- `pop` — успех/иконки: 0.45–0.5s `cubic-bezier(0.34,1.56,0.64,1)`.
- `spin` — лоадер оплаты, 0.9s linear.
- `fadeIn` — оверлеи/бэкдропы, 0.2–0.25s.
- `drawerIn` — карточка заведения справа: `translateX(30px)→0` + fade, 0.3s `cubic-bezier(0.2,0.8,0.2,1)`.
- Scroll-reveal на лендинге: элементы `[data-reveal="N"]` стартуют `opacity:0; translateY(26px)`, проявляются через IntersectionObserver (threshold 0.15) с каскадной задержкой `N*110ms`, transition 0.65s `cubic-bezier(0.22,0.65,0.3,1)`. **Уважать `prefers-reduced-motion: reduce`** — без анимации.
- Splash-заставка плеера между треками: `injIn` 0.4s + удержание ~2.4s/√speed.
- Toast: автоскрытие 2600ms.

## Screens / Views

### 0. Хаб прототипа — `Trekni Prototype.dc.html` (точка входа, desktop)
**Назначение:** единый вход, карта пути ценности (6 шагов: скан QR → выбор → оплата СБП → очередь → плеер → выплата, окрашены по ролям) и сетка карточек-ссылок на все экраны. Макс. ширина 1120px. Каждая карточка — `<a href>` на соответствующий `.dc.html`.

### 1. Лендинг для заведений — `Trekni Landing.dc.html` (desktop)
**Назначение:** продать сервис и дать зарегистрироваться самостоятельно (без менеджера).
**Layout:** sticky-навбар (лого + якорные ссылки + CTA «Подключить заведение»); герой в 2 колонки (текст + рамка iPhone с превью гостевого экрана); далее секции по якорям.
**Секции:** Как работает (4 карточки-шага) · Контроль (4 карточки: плейлист, своя цена [интерактивный ±], стоп-кран приёма [тоггл], «музыка не останавливается» — фон ∞) · **Легальность** (журнал воспроизведений, отчёты РАО/ВОИС, «Скачать пакет документов»; формулировка: помогаем оформить и вести отчётность, стороной договоров остаётся заведение) · Доход (интерактивный калькулятор: слайдеры «заявок за вечер» 5–60 и «цена» 99–499 → выручка/комиссия/чистыми в месяц; комиссия — prop) · Брендинг (превью с выбором акцентного цвета — платная опция) · **Тарифы** (3 карточки) · Отзывы (3 карточки, роли — владелец/владелец/совладелец) · FAQ (аккордеон) · Регистрация (форма: название + email → экран успеха со ссылкой «Открыть кабинет») · футер.
**Тарифы:**
- **Старт** — 0 ₽/мес, комиссия **20%**: страница+QR, плейлист/цена/фон, СБП+выплаты раз в неделю, журнал воспроизведений.
- **Легал** — 2 490 ₽/мес, комиссия **10%** (помечен «Популярный»): всё из «Старта» + документы РАО/ВОИС (месячные отчёты) + напоминания о сроках + статистика + QR по зонам + ежедневные выплаты.
- **Всё включено** — 5 990 ₽/мес, комиссия **7%**: всё из «Легала» + сопровождение РАО/ВОИС (подача отчётов, платежи, акты) + брендинг страницы + мультизаведения + перс. менеджер.
**Анимации:** scroll-reveal (см. Motion). **Prop:** `commission` (int, 5–30, дефолт 15) — влияет на пример в калькуляторе.

### 2. Гостевой флоу — `Trekni Guest Flow.dc.html` (mobile, в рамке iPhone)
**Назначение:** без регистрации понять цену, найти трек, оплатить, увидеть, что заявка принята.
**Экраны/состояния (одно устройство, переключение состояний):**
- **Плейлист (home):** шапка (лого, RU/EN тоггл), название заведения + адрес + статус приёма + чип цены; «Сейчас играет» с эквалайзером и метой очереди; строка поиска; чипы-жанры (Все/Поп/Рок/Хип-хоп/2000-е); список треков (обложка-заглушка с моно-тегом, название, исполнитель·длительность, кнопка +/✓); нижний CTA «Заказать за 199 ₽» (неактивен, пока трек не выбран) + «Оплата через СБП · без регистрации». Поиск и жанры реально фильтруют; тап по треку выбирает (подсветка акцентом). При фокусе на поиск показывается клавиатура (`keyboard` рамки) и CTA прячется.
- **Оплата (шит снизу):** ручка, заголовок, выбранный трек, чек (строка/итого), «Оплатить через СБП», сетка из 4 банков (Сбер/Т-Банк/Альфа/ВТБ); тап по банку → **processing** (спиннер, «ждём подтверждение…», отмена) → успех или ошибка.
- **Ошибка оплаты:** красная иконка, «Оплата не прошла», «Банк отклонил / таймаут. Деньги не списаны — заявка не создана», «Попробовать ещё раз» / «Отмена».
- **Очередь / успех:** зелёная галочка (pop), «Заявка принята!», № заявки и оплачено, крупный «№4» + позиция + ETA, список очереди (впереди идущие + свой трек с бейджем «твой трек» + строка «дальше — плейлист заведения, фон играет сам»), «Заказать ещё трек».
- **Приём закрыт:** красный статус в шапке, баннер-объяснение, плейлист приглушён (opacity 0.45, без выбора), CTA задизейблен «Приём заявок закрыт».
**Демо-панель** под устройством (не часть продукта): переходы Плейлист/Оплата/Ошибка/Очередь, переключатели «исход оплаты» и «приём», сброс.
**Props (платная кастомизация заведения):** `venueName` (text), `price` (int 49–999), `accent` (color, палитра из 4).

### 3. Кабинет владельца — `Trekni Owner Cabinet.dc.html` (desktop)
**Назначение:** управлять заведением и видеть деньги/статистику.
**Layout:** левый sidebar (лого, пункты навигации, ссылки на страницу гостя и плеер, профиль) + основная область с topbar (заголовок секции, бейдж тарифа+комиссии, пилюля статуса приёма, селектор заведения).
**Разделы:**
- **Обзор:** 4 KPI (заявок сегодня, выручка, в очереди, баланс к выплате), график заявок за неделю (бары), топ треков, «последние заявки» (со статусами в очереди/проиграно/отклонено·возврат).
- **Статистика:** 4 KPI + переключатель периода **7/30 дней**, бар-чарт заявок по дням, заявки по часам (пик 22–23), сканирования по точкам (горизонтальные бары), топ треков, «источник проигрываний» (заявки 32% / фон 68%).
- **Плейлист:** поиск + «добавить трек», строка статистики доступности, **баннер «Бесконечный фоновый режим»** (тоггл: между заявками играет фон, а не тишина), список треков с жанром/статистикой и тогглом видимости для гостей (выкл. трек гость не видит).
- **QR-точки:** карточки зон (QR-заглушка, число сканирований, «Скачать PNG»/«Тейбл-тент») + «добавить точку».
- **Выплаты:** баланс к выплате + «Вывести сейчас», реквизиты, история выплат.
- **Юр. чистота:** при тарифе «Старт» — заглушка-апселл; иначе 3 карточки (договор РАО/ВОИС/сопровождение), список отчётов РАО/ВОИС + «Скачать пакет документов», **журнал воспроизведений** (время, трек, источник фон/заявка, длительность; фиксируется каждое публичное воспроизведение, хранение 3 года).
- **Настройки:** цена заявки (±), приём заявок (тоггл; блокируется, если включено расписание), **расписание приёма** (тоггл + недельная сетка пн–вс с интервалами from–to, поддержка «через полночь» = ночная смена, статус «сейчас открыт/закрыт по расписанию»), язык страницы по умолчанию, **брендинг** (при «Всё включено» — превью + выбор акцентного цвета + тоггл «логотип вместо Трекни»; иначе — апселл), выбор тарифа.
**Тосты** на действия. **Prop:** `tariff` (enum: Старт/Легал/Всё включено, дефолт «Легал») — гейтит брендинг и юр.раздел.

### 4. Плеер заведения — `Trekni Player.dc.html` (экран 16:9 у колонок)
**Назначение:** автоматическое воспроизведение без диджея.
**Layout:** дисплей 16:9 (радиус 22, свечение акцентом). Топбар: название заведения, статус «приём открыт», часы. Две колонки: **«Сейчас играет»** (эквалайзер, чип источника ЗАЯВКА/ФОН, крупная обложка+название+исполнитель, прогресс-бар с таймингами) и **«Далее в очереди»** (список: заявки помечены акцентом, затем строка «Фоновый плейлист ∞»). Нижняя плашка-подсказка: QR + «Закажи свой трек — 199 ₽» + счётчик заявок за вечер.
**Логика воспроизведения:** заявки играют первыми (вклиниваются после текущего трека, перед фоном); когда заявок нет — бесконечный фон в случайном порядке, хвост очереди дозаполняется фоном (пауз/тишины не бывает). **Заставка-переход между треками** (`splash`): брендовый сплэш «Далее / Заявка гостя» с обложкой и эквалайзером на ~2с при каждой смене трека, затем переключение.
**Демо-контролы:** пауза, следующий трек, «+ заявка гостя» (вставляет заявку с flash-подсветкой), скорость 1×/8×/30×. **Prop:** `accent` (color).

### 4b. Пульт смены — `Trekni Remote.dc.html` (mobile, в рамке iPhone)
**Назначение:** быстрое управление воспроизведением «с телефона», не подходя к плееру. **Доступ только из кабинета заведения** (ссылка в сайдбаре) — не публичный экран.
**Layout:** мобильная страница. Шапка (‹ назад в кабинет, «Пульт», название заведения, статус «плеер онлайн»). Карточка «сейчас играет» (чип источника фон/заявка, обложка, название/исполнитель, прогресс, транспорт: ↺ сначала · ⏯ пауза/играть [крупная акцентная кнопка] · ▸▸ следующий). Блок «Громкость» (иконка динамика с уровнем/мьютом, слайдер с заливкой акцентом, % и пресеты 25/50/75/Макс). Список «Очередь» (заявки помечены акцентом; действия в строке: ↑ поднять, ▶ играть сейчас, ✕ убрать) + строка «фоновый плейлист ∞». Внизу — тоггл «Приём заявок».
**Интеракции:** play/pause (эквалайзер анимируется только при playing), скип/рестарт, слайдер+пресеты громкости и мьют, «играть сейчас» (переносит трек в текущий), «поднять» (меняет порядок в очереди), удаление (для заявки гостя → возврат 199 ₽), тоггл приёма. Тосты на действия. **Prop:** `accent` (color).
**Прод:** тонкий клиент-пульт к тому же плееру — реалтайм-синхрон с `Trekni Player` (громкость устройства и очередь заведения).

### 5. Админка платформы — `Trekni Admin.dc.html` (desktop)
**Назначение:** управлять заведениями, модерацией, финансами, спорами.
**Layout:** sidebar (пункты с бейджами-счётчиками на «Модерация» и «Споры», профиль админа) + topbar.
**Разделы:**
- **Обзор:** 4 KPI (заведений всего/активных, оборот за месяц GMV, комиссия платформы, «требует внимания» → модерация/споры), график GMV по месяцам, распределение заведений по тарифам, лента событий (точки-статусы).
- **Заведения:** поиск + фильтры (Все/Активные/На модерации/Заблокированы), таблица (моно-аватар, название, город, дата, тариф, оборот/мес, статус-бейдж, ›). Клик по строке → **Карточка заведения** (drawer справа).
- **Карточка заведения (drawer):** аватар, название, город, дата; статус-бейдж; 4 KPI (оборот, заявок, средний чек, комиссия платформы); инфо-лист (тариф + «сменить» = циклическая смена, владелец, контакт, размер плейлиста); плашка по открытым спорам заведения; действия: **Заблокировать/Разблокировать** или (для «на модерации») **Подтвердить подключение** + «Отклонить заявку»; «Открыть кабинет заведения». Все действия меняют данные вживую и дают тост.
- **Модерация:** заявки на подключение (Подтвердить → заведение появляется в списке как активное на «Старте» / Отклонить) + жалобы на контент (Снять трек / Отклонить). Пустые состояния.
- **Финансы:** визуализация «как делятся деньги гостя» (гость платит → доля заведений 89,5% + комиссия платформы 10,5%); формулировка про роль **платёжного участника** (сбор оплат СБП, удержание комиссии по тарифу, формирование выплат); список выплат заведениям (pending → «Провести выплату» → done).
- **Споры:** карточки (тег #G-XXXX, заведение, сумма, текст обращения); решение: **«Вернуть гостю» (возврат из доли заведения)** или «В пользу заведения»; после решения — статус.
**Тосты** на все действия. Комиссии по тарифам: Старт 20% / Легал 10% / Всё включено 7%.

## Interactions & Behavior (сводно)
- **Навигация:** хаб и футеры/сайдбары связывают экраны обычными ссылками. В реальном приложении гость и заведение — разные приложения/зоны; QR-ссылка гостя параметризована id заведения.
- **Выбор трека → оплата → результат:** оптимистичных списаний нет; при ошибке явно «деньги не списаны». Возврат при отклонении заявки — автоматический.
- **Приём заказов:** ручной тоггл ИЛИ расписание (недельные интервалы, ночные смены через полночь). Когда закрыт — гость видит соответствующее состояние, заказ недоступен.
- **Фоновый плейлист:** бесконечный, заявки приоритетны и вклиниваются после текущего трека; заставка-переход между треками.
- **Модерация/споры/выплаты (админка):** действия немедленно меняют состояние списков и показывают тост; счётчики в навигации живые.
- **Состояния:** loading (спиннер оплаты), error (ошибка оплаты), empty (нет заявок на модерации/жалоб, пустой поиск), disabled (CTA без выбора, приём закрыт), success (принято/выплачено/подключено).

## State Management (что понадобится в проде)
- **Гость:** `venueId`, каталог плейлиста заведения, `query`, `genre`, `selectedTrack`, `lang`, статус заявки (`idle|paying|processing|error|queued`), позиция в очереди (реалтайм).
- **Заведение:** плейлист (треки + флаг видимости), `price`, приём (`open` / `schedule[7]` с from/to и overnight), `backgroundMode`, `tariff`, брендинг (`accent`, `ownLogo`), статистика (агрегаты по периодам), выплаты/реквизиты, журнал воспроизведений.
- **Плеер:** `current` (+источник req/bg), `elapsed`, `queue[]` (заявки приоритетны, хвост из фона), `playing`, `splash` (переход).
- **Пульт смены:** те же `current`/`queue`/`playing`, плюс `volume`/`muted`, `accept`; операции play/pause, skip, restart, playNow, moveUp, remove(+возврат) — команды к плееру по реалтайм-каналу.
- **Платформа:** заведения (+статус/тариф/метрики), очередь модерации (подключения + жалобы), выплаты (pending/done), споры (open/refunded/venue), агрегаты GMV/комиссии.
- Реалтайм: очередь и «сейчас играет» синхронизируются между гостем, плеером и кабинетом (WebSocket/подписки). Оплата — СБП (создание заявки → подтверждение банком → колбэк → постановка в очередь).
